# ToMD 마크다운 변환기

문서 파일을 마우스 오른쪽 버튼 메뉴에서 바로 마크다운(.md)으로 변환하는 Windows 프로그램입니다.

## 사용법

1. 이 저장소의 **Releases**에서 `ToMD-Setup.exe`를 내려받아 실행합니다.
2. 변환할 파일을 마우스 오른쪽 버튼으로 누르고 **마크다운(MD)으로 변환**을 선택합니다.
   Windows 11에서는 **추가 옵션 표시**를 먼저 누르거나 Shift+오른쪽 버튼을 사용합니다.
3. 원본과 같은 폴더에 같은 이름의 `.md` 파일이 생깁니다. 같은 이름이 이미 있으면 `이름 (2).md`로 저장합니다(기존 파일은 덮어쓰지 않음).
   같은 내용의 원본을 같은 버전으로 이미 변환했다면 새로 만들지 않고 건너뜁니다. 원본이 바뀌었거나 ToMD가 새 버전이면 새 파일을 만듭니다.

폴더를 오른쪽 버튼으로 누르거나, 폴더를 연 상태에서 빈 곳을 오른쪽 버튼으로 누르면 폴더(하위 폴더 포함) 안의 문서를 한꺼번에 변환합니다. 변환할 문서가 하나도 없으면 그렇다고 알려 줍니다.

Windows 11에서는 오른쪽 클릭 후 '더 많은 옵션 표시'(Shift+F10)를 눌러야 메뉴가 보입니다.

변환이 오래 걸리면 진행 창이 떠서 진행률을 보여주고, 취소할 수 있습니다. 여러 파일을 선택해도 창은 하나만 뜹니다.

## 지원 형식

| 형식 | 확장자 | 비고 |
| --- | --- | --- |
| PDF | pdf | 글자가 들어 있는 PDF만 지원. 스캔본(OCR)은 지원하지 않음. 가로로 누운 쪽은 바로 세워 변환 |
| 한글 | hwp, hwpx | 글과 표를 변환. 암호 문서와 배포용 문서는 지원하지 않음 |
| 엑셀 | xlsx, xlsm, xls, csv, tsv | 시트별 표로 변환. 화면에 보이는 숫자 모양(쉼표·%·△) 그대로. 차트·그림은 개수, 도형·단추 속 글은 목록으로. 매크로(VBA) 코드는 맨 끝에 코드 블록으로 (실행하지 않음). 코드 속 비밀번호·접속 정보·개인 경로·IP·이메일·전화번호로 보이는 곳은 `****`로 가림 |
| 워드 | docx | 제목, 목록, 굵게/기울임, 표, 글상자 속 글(따로 문단으로) |
| 개방형 문서 | odt | 한글·LibreOffice 등에서 저장한 ODT. 제목, 목록(번호 포함), 굵게/기울임, 링크, 병합된 표, 각주, 글상자 |
| 파워포인트 | pptx | 슬라이드별 제목, 글, 표, 발표자 노트. 숨긴 슬라이드는 (숨김)으로 표시하고 그림은 개수만 적음 |
| 텍스트 | txt | 탭으로 나뉜 표(엑셀의 '텍스트(탭으로 분리)' 저장)는 표로, 그 밖에는 줄바꿈을 살린 글로. 한글 인코딩(UTF-8·ANSI) 자동 판별 |
| 웹 페이지 | html, htm | 제목·문단·목록·표(병합 칸)·링크·굵게를 마크다운으로. 스크립트·숨긴 부분은 뺌 |

- 병합된 셀이 있는 표는 마크다운 문법으로 표현할 수 없어 HTML 표로 출력합니다. PDF의 표는 병합을 풀어 마크다운 표로 출력합니다.
- PDF 글꼴에 문자 정보가 없어 숫자가 읽히지 않는 경우, 글자 번호 규칙을 찾아 복원하고 해당 쪽 머리에 복원했다는 안내 문구를 넣습니다. 규칙을 찾지 못하면 읽지 못한 글자 수를 안내합니다.
- 그림자·윤곽 효과로 여러 번 겹쳐 찍힌 제목 글자는 한 번만 내보냅니다.
- 세로선이 없는 표는 칸을 나누지 않고 행마다 한 줄씩 내보냅니다.
- 그림은 변환하지 않습니다.
- 변환 결과 맨 위에 문서 정보(원본 파일, 형식, 쪽·슬라이드·시트 수, 변환 시각, `converter: "ToMD 1.0.13"` 같은 프로그램 버전)가 YAML 머리말로 들어갑니다. 진행 창 제목에도 같은 버전이 표시되며, GitHub Releases의 번호와 같습니다.
- 옵시디언(Obsidian)에서 그대로 쓸 수 있습니다. 머리말은 '속성'으로 보이고 `ToMD` 태그가 붙습니다. PDF는 `## 12쪽`처럼 쪽마다 소제목이 있어 개요에서 쪽으로 이동하거나 `[[문서#12쪽]]`으로 연결할 수 있습니다.
- 변환에 실패하면 안내 창이 뜨고, 자세한 내용은 `%LOCALAPPDATA%\ToMD\log.txt`에 기록됩니다.

## 문서 식별과 메타데이터 (옵시디언·업무 프로그램 연동)

변환 결과 머리말에 v19 항목 뒤로 다음 항목이 덧붙습니다. 본문은 v19와 같습니다.

| 항목 | 뜻 |
| --- | --- |
| `doc_id` | 문서의 논리적 식별자(UUID). 처음 변환할 때 만들고, 같은 자리의 원본을 수정해 다시 변환하거나 원본을 옮겨도 유지 |
| `content_hash` | 원본 파일의 SHA-256 (내용이 바뀌면 달라짐) |
| `source_path` | 원본 경로. 폴더를 변환했으면 그 폴더 이름부터의 상대 경로, 파일 하나면 파일 이름 (컴퓨터 사용자 이름 같은 절대 경로는 넣지 않음) |
| `source_size`, `source_modified` | 원본 크기(바이트)와 수정 시각 |
| `project_id`, `year`, `document_type` | 사업 식별자·사업 연도·문서 종류. **지정한 값만** 들어가고 모르면 빈 값 (추측하지 않음) |
| `converter_version` | 변환한 ToMD 버전 |
| `id_status` | `new` 처음 등록 · `same_path` 같은 자리의 문서 · `moved` 옮겨진 문서 · `assigned` 지정한 doc_id · `check` 확인 필요 |
| `id_candidates` | `check`일 때 같은 문서일 수 있는 doc_id 목록 |
| `review` | 사람이 확인할 일 (예: `미지정: project_id, year, document_type`, doc_id 확인 필요, 메타데이터 설정 오류) |
| `status`, `warnings` | `ok` 또는 `warning`과 변환 품질 경고 (스캔 PDF, 글자 없는 쪽, 복원한 숫자, 계산값 없는 수식 칸, 숨긴 시트, 가린 매크로 정보 등) |
| `tomd_schema` | 머리말 형식 번호 (지금은 1) |

**doc_id를 정하는 규칙** — 문서등록 기록(`%LOCALAPPDATA%\ToMD\registry.json`)에 원본 위치·해시·변환본을 적어 두고 비교합니다.
- 같은 위치의 원본이면 내용이 바뀌어도 같은 doc_id.
- 같은 내용의 원본이 다른 위치에 등록되어 있고 원래 위치에 파일이 없으면 옮긴 것으로 보고 같은 doc_id (`moved`).
- 같은 내용의 파일이 다른 위치에 아직 있으면(복사본, 다른 사업의 같은 양식 등) **자동으로 합치지 않고** 새 doc_id를 준 뒤 `check`로 표시합니다. 같은 문서가 맞으면 `tomd-meta.json`에 그 doc_id를 지정하세요.

**메타데이터 지정** — 우선순위: 명령행 `--meta` > 파일별 지정 > 폴더 공통값(가까운 폴더 우선) > 자동 추출(없음).
문서가 있는 폴더와 그 위 5단계까지의 `tomd-meta.json`을 읽습니다. 없어도 오른쪽 클릭 변환은 그대로 됩니다.

```json
{
  "project_id": "S048",
  "year": 2027,
  "files": {
    "운영계획*.hwp": { "document_type": "운영계획" },
    "결과/*.pdf":    { "document_type": "결과보고" },
    "안내.hwpx":     { "document_type": "안내공문", "doc_id": "기존-doc_id" }
  }
}
```

`files`의 이름은 그 `tomd-meta.json`이 있는 폴더 기준 경로나 파일 이름이며 `*`, `?`를 쓸 수 있습니다. 위 표의 ToMD 항목(`title`, `content_hash` 등)은 지정해도 쓰지 않습니다.

**다른 프로그램에서 부르기** (창 없이 실행)

```
ToMD.exe --input 파일또는폴더 [--input ...] [--output 결과폴더]
         [--meta project_id=S048 --meta document_type=결과보고]
         [--if-exists new|skip|overwrite|always]
         [--registry 기록.json | --registry none] [--report 결과.json]
```

- `--output`: 결과 폴더. 폴더를 변환하면 하위 폴더 구조를 그대로 만듭니다. 생략하면 원본 옆에 저장.
- `--if-exists`: `new`(기본, 같은 내용·같은 버전이면 건너뛰고 아니면 새 파일) · `skip`(변환본이 있으면 건너뜀) · `overwrite`(`이름.md`를 바꿈, 명시했을 때만) · `always`(늘 새 파일)
- `--report`: 파일별 결과(converted/skipped/failed, 결과 경로, doc_id, content_hash, id_status, review, warnings, 메타데이터)를 JSON으로 저장. 설치본은 창 없는 프로그램이라 화면 출력 대신 이 파일을 읽으세요.
- 종료 코드: `0` 모두 성공(건너뜀 포함) · `1` 일부 실패 · `2` 인수 오류

## 빌드

`main` 브랜치에 올리면 GitHub Actions가 설치 파일을 만들어 Releases에 게시합니다.
직접 빌드하려면 Python 3.12와 Inno Setup 6을 설치한 뒤 `.github/workflows/build.yml`의 명령을 순서대로 실행합니다.

## 제거

Windows 설정 → 앱 → 설치된 앱에서 **ToMD 마크다운 변환기**를 제거하면 메뉴도 함께 사라집니다.
